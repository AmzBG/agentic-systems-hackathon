Scaled Dot-Product Attention: From Scores to Weights to Output

Audience: Second-year engineering undergraduate who knows vectors, matrices, and basic probability but has not studied Transformers.

Plan: This page teaches scaled dot-product attention by letting the learner edit a query row, a key matrix, and a value matrix, then observing how raw dot products are scaled, turned into softmax weights, and combined into an output vector. Two explorations contrast equal scores with a dominant score and show the effect of the 1/sqrt(dk) scaling.

Starting point

Idea: Scaled dot-product attention computes a compatibility score between a query and each key, normalizes these scores into a probability distribution with softmax, and returns a weighted sum of the values.

Why it matters: It is the core operation of the Transformer's attention, allowing each position to focus on relevant positions.

Explanation: Edit the query matrix Q (one row, four numbers), the key matrix K (two rows, four numbers), the value matrix V (two rows, two numbers), and toggle scaling. The raw dot product readout raw_dot shows q·k_i for each key row. The scale_factor readout is 1/sqrt(dk) when scaling is on and 1 when off, where dk is the number of columns in Q and K. The scaled scores readout multiplies raw_dot by scale_factor. The attention weights readout applies softmax to scores, and weight_sum confirms the weights sum to one. Finally, the output readout is the weighted sum of the value rows using those weights.

Equal scores produce uniform attention

Predict: Predict: if two keys give the same score, what will the attention weights and output be? Then apply the preset, which sets Q and K to make raw dot products equal.

Compare your prediction

Observe: The weights readout becomes [0.5, 0.5] and weight_sum stays 1; the output becomes [0.5, 0.5] because V is the identity matrix. The scores bar shows equal bars.

Explain: Softmax of equal scores gives each key the same weight, so the output is the average of the value vectors. Scaling does not change equality.

A dominant score with scaling off

Observe: The weights readout becomes approximately [0.982, 0.018] and weight_sum stays 1; the output is nearly the first value vector. Turning scaling on would flatten the weights.

Explain: Without scaling, the large score gap makes softmax saturate, assigning almost all weight to the first key. The scale_factor is 1 instead of 1/sqrt(dk)=0.5, so score differences are not reduced.

Limitation

This page uses a single query (one row in Q) and only two keys, so it does not show the full matrix-of-queries calculation or masking. The softmax normalization is numerically stabilized by subtracting the maximum score, which does not change the resulting weights. The identity value matrix V makes the output equal to the weights, which is a special case; editing V shows the general weighted sum.
